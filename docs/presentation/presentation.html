Problem Statement & Fundamentals

Understanding Distributed Denial of Service (DDoS)

A coordinated cyber assault exhausting network bandwidth, switch memory, or application threads.

1. Volumetric Reflection
• Attack Vectors: DNS, NTP, LDAP, SSDP, MSSQL Amplification.
• Mechanism: Forged requests reflect packets 50x–100x larger onto the victim.
• Metric: Gigabits/sec (Gbps) & Terabits/sec.
2. Protocol / State-Exhaustion
• Attack Vectors: TCP SYN Flood (Neptune), Smurf, SDN OpenFlow saturation.
• Mechanism: Blasts uncompleted SYN handshakes, filling OS socket queues.
• Metric: Packets/sec (pps).
3. Application-Layer Stealth
• Attack Vectors: Slowloris, Slowhttptest, HTTP GoldenEye/Hulk.
• Mechanism: Slowly transmits headers, starving web server worker threads with low bandwidth.
• Metric: Requests/sec (rps).
Core Challenge: Modern enterprise clouds, software-defined networks (SDN), and IoT gateways face all three attack types simultaneously across completely different packet schemas.
Literature Gap Analysis

The 4 Fatal Flaws in Existing Research Papers

Why traditional machine learning intrusion detection systems fail when deployed in real networks.

Flaw 1: The Single-Dataset Silo
Over 90% of papers train on only ONE dataset (e.g. only InSDN or only CIC-DDoS2019). When deployed on IoT or Enterprise switches, models collapse due to radical schema mismatch.
Flaw 2: The Recurrent Latency Bottleneck
State-of-the-art papers use heavy BiLSTMs or Transformers taking 25–40 ms per flow. At 10 Gbps (1.48 million pps), switch queues buffer-overflow before inference finishes!
Flaw 3: The Passive Alert Trap
Almost all academic papers stop at printing a test score or confusion matrix. They provide ZERO closed-loop mitigation to actually protect routers, switches, or host computers.
Flaw 4: Hardware & OOM Collapse
Code relies on unbatched tensors, causing out-of-memory kernel panics on edge gateways and local workstations lacking massive cloud clusters.

Detection Mechanics

On What Exact Mathematical Basis Does AI Detect DDoS?

Rigorous information theory and state machine verification.

1. Shannon Entropy Collapse
H(X) = - Σ p(x_i) log2 p(x_i)
• Normal Traffic: High entropy ($H \ge 4.5$) due to natural variety in ports and packet sizes.
• DDoS Floods: Collapsed entropy ($H < 1.8$) because botnets spam identical, cloned packets.
2. Flow Symmetry & Bidirectionality
Asymmetry = |Pkts_Fwd - Pkts_Bwd| / Pkts_Total
• Normal Browsing: Two-way conversation ($1:1$ or $1:2$).
• DDoS Attacks: 100% asymmetry (all forward packets, zero response).
3. TCP Handshake State Machine
• Verifies RFC 793 lifecycle (SYN → SYN-ACK → ACK).
• Detects Neptune floods where SYN=1, ACK=0 across thousands of sessions.
4. Focal Loss Optimization
L_focal = -α_t (1 - p_t)^γ log(p_t)
• Down-weights easy normal packets ($\gamma=2.0$).
• Forces the neural network to master subtle, hard zero-day attack boundaries.

Autonomous Mitigation & The "Ambiguous Burst"

Why downloading a 4K movie or a Black Friday flash crowd never gets blocked.

PASS (P < 15%)

Hardware Engineering

Hardware Acceleration & Edge Survivability

Engineered for Apple Silicon MPS, NVIDIA CUDA, and bounded-memory gateways.

The Edge Gateway Challenge
• IoT edge routers and local workstations have restricted RAM (8–16 GB).
• Unbatched tensor execution causes out-of-memory kernel panics.
• Double-precision float64 tensors trigger PyTorch MPS backend errors on Apple Silicon.
Our Hardware Solutions
• Strict Float32 Encodings: Seamless execution on Apple M-series GPUs.
• Sequential Mini-Batching: Explicit torch.mps.empty_cache() flushes strictly bound memory to < 150 MB RAM.
• Auto-Device Detection: Automatically configures between MPS, CUDA, and CPU SIMD instructions.
